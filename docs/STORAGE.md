# Форматы файлов

Данные локальные и не отправляются в сеть. По умолчанию каталог `~/.battle-arena`, переопределяется параметром `--data-dir`.

## Слоты

`slot-1.json`, `slot-2.json`, `slot-3.json`. Корневые поля:

- schema_version: целое 1;
- rules_version: целое 1;
- saved_at: ISO 8601;
- battle: полный снимок боя.

Снимок содержит match_id, mode (`pvp`/`bot`), strategy (`aggressive`/`cautious`), phase, active_id, turn, successful_actions, fighters, events, next_event, winner_id и finish_reason. Фаза — WAITING_ACTION или FINISHED.

У бойца сохраняются id, name, archetype, equipment, итоговые stats, hp, energy, inventory, effects, last_action_id и totals. Инвентарь — пары `[item_id, quantity]`. Эффект содержит effect_id, source_id и remaining; владелец определяется бойцом, внутри которого эффект находится.

События имеют последовательные номера, номер хода, kind, actor_id, target_id, action_id, calculated, actual и remaining. Счётчик действий совпадает с числом событий action. Статистика делит прямой урон, яд, лечение и предметы.

JSON проходит проверку полей, типов и связей. Bool не считается целым. Неизвестные поля, типы эффектов, архетипы и действия отклоняются. Проверяются ресурсы, соответствие характеристик экипировке, инициативы/чередования, согласованность фазы, счётчики, источники эффектов и исход.

Повторные ключи JSON запрещены. Ограничение слота — 2 000 000 байт. Это проверка корректности состояния, а не криптографическая защита от ручного редактирования; воспроизведение всего журнала для доказательства каждой исторической цифры не выполняется.

Запись: временный файл в том же каталоге → json.dump → flush/fsync → закрытие → replace. При ошибке старый файл остаётся, временный удаляется по возможности. Это не гарантия сохранности при любом отказе устройства.

## История

`history.json`: schema_version и matches, не более 50 записей. Запись содержит completed_at и document с законченным снимком. Полный снимок позволяет показать не только итоговую статистику, но и журнал выбранного матча. match_id исключает повторное добавление. Для 50 длинных журналов установлен отдельный лимит 32 000 000 байт.

Повреждённая история не перезаписывается автоматически. Ошибка её записи не отменяет результат боя и видна пользователю. Очистка доступна после подтверждения.

## Настройки

`settings.json`: bot_delay_ms (целое 0–3000) и font_size (целое 10–20). Отсутствующие поля получают значения 300 и 12. Неизвестные поля и неверные типы отклоняются. При повреждении настроек приложение сообщает ошибку и использует значения по умолчанию до явного сохранения новых настроек.

## Ошибки и согласованность журнала

StorageError предоставляет стабильный StorageCode, message, path и recovery; details() возвращает структурированные сведения. Различаются отсутствие файла, ошибки чтения/записи, размер, кодировка, JSON, схема, версия, настройки, история, слот и отсутствие матча. Сообщения пользователю остаются человекочитаемыми.

Статистика урона, лечения и использованных предметов сверяется с фактическими событиями. Последнее действие каждого бойца также сверяется с журналом. Просмотр истории использует тот же формат версии 1 и ничего не записывает в исходный матч.
